# Skills Scorecard — rated for *performance*, not knowledge

Rating standard (per Theo, 9 Jun 2026): the gold standard is **"can this repeatedly
produce the desired outcome in the real world?"** — Results beat theory.

Each curated skill is scored **K × E × R × T**, 1–10 each, **/40**:

| Dim | For a skill *playbook*, the question is… |
|---|---|
| **K** Knowledge | Does it encode the proven know-how (frameworks, data)? |
| **E** Execution | Can you actually *do* it from this — steps, templates, thresholds? |
| **R** Results | Does following it move the lead-gen needle (leads / rankings / conversions)? |
| **T** Teaching | Does it explain *why*, so the user/AI adapts to new cases? |

Mastery ladder (Dreyfus): Novice → Advanced Beginner → **Competent (L4)** →
**Proficient (L5)** → **Mastery (L6)** → Authority (L7). A skill scoring ≥34
is an Authority-tier playbook; 28–33 Proficient; 24–27 Competent; <24 = cut.

## The honest "where are we?" read

A skill document can only carry **Knowledge, Execution, and Teaching**. **Results**
— the dimension Theo (correctly) ranks first — cannot be proven by a playbook; it
only shows up once pages are live and leads are measured.

So on the ladder, this library puts the engine at **L5 Proficiency on paper**: it
can produce good, consistent, well-reasoned lead-gen writing and explain why. To
reach **L6 Mastery / L7 Authority** we need the missing input: **real outcome data**
(which page/headline/offer actually generated qualified leads) fed back in — i.e.
the measurement loop. Theory is loaded; results are earned in production.

> Scores are judgments from a structured audit of each SKILL.md, not measured
> conversion data. Re-score against real lead/conversion results once live.
