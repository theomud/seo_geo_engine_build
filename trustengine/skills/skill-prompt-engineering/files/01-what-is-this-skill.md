# Skill · File 01 — What This Skill Is
## Niche-agnostic definition of Prompt Engineering

---

## The problem this skill solves

Most people use AI like a search engine: they type a vague question and hope for a useful answer. The result is generic, on-average, unusable output — every time. The cost is hidden but large: hours of rewriting, or worse, publishing bland content that builds no trust.

Prompt Engineering reframes the interaction. **The prompt is not a question — it is a creative brief.** You treat the model like a skilled team member who needs clear instructions: who they are, who they're writing for, what to produce, with what facts, under what constraints, to what standard. The more specific and structured the brief, the better the draft. The goal is **70%+ usable output without heavy rewriting**, for any content type, any niche, any business.

---

## What this skill produces

| Output | What it is |
|--------|-----------|
| The 9-element prompt | A complete brief — the unit of work this skill produces |
| A prompt template library | One reusable template per content type (landing page, SEO article, service page, FAQ, location page, comparison, rewrite, meta tags) |
| A personal prompt archive | Every prompt that worked, saved for reuse — value compounds over time |

The template library and archive are the durable asset — the skill is not "write one good prompt," it is "build a library that makes every future draft 70%+ usable on the first pass."

---

## The 9 elements

Every strong prompt contains all nine: **Context · Role · Objective · Audience · Inputs · Constraints · Examples · Output Format · Quality Criteria.** Each missing element produces a predictable failure — no Audience → generic reader; no Quality Criteria → no standard to aim for; no Examples → the model guesses your style. *(Library: M-09 Nine-Element Prompt Model.)*

**The Minimum Viable Prompt** for quick tasks: **Context + Role + Objective + Output Format** — the four below which output reliably degrades. Never fewer than these.

Two published cousins are worth knowing and are catalogued in the library: **COSTAR** (Context, Objective, Style, Tone, Audience, Response — M-16) and **PICO/TCEPFT** (M-17). The 9-element model is the superset this skill teaches; Google's canonical core is 4 (Role/Task/Context/Format).

## A worked example (the proof niche)

A vague prompt — *"write a page about pet relocation to Dubai"* — returns marketing mush. The 9-element version for the airport-confiscation page:

> **Context:** Dubai pet relocation, a maximum-risk regulated market; customers arrive afraid. **Role:** a relocation specialist who has cleared pets through MOCCAE. **Objective:** a 700-word Fear Resolution page answering "what happens if my dog is taken at the airport." **Audience:** an owner who read their dog could be confiscated. **Inputs:** Verified Source Bank rows C-019 (permit online), C-010 (90-day validity), C-003 (500 AED release fee); community quote (Muze Gu). **Constraints:** open with the fear in the owner's words; cite every fact by C-ID; hedge the titer cost (C-001, no official figure); no "Get a Quote." **Examples:** the 5-layer structure. **Output Format:** the 5 layers, markdown. **Quality Criteria:** every claim traces to a Verified row; passes the Hormozi "would you put your name on it" test.

That prompt produces a usable first draft of a real page — not mush.

## Why this is a standalone skill

1. **It is the input multiplier.** Every content skill downstream produces better first drafts when the prompt is engineered — the lift compounds across the whole system.
2. **The library is a reusable asset.** Templates + archive are built once and reused on every page, and are licensable.
3. **It is the most teachable skill in the collection (5/5).** The 9 elements are copyable; a beginner reaches 70%+ usable output in two weeks of practice.

---

## How it differs from "just asking AI"

| Just asking | Prompt Engineering |
|-------------|--------------------|
| A question | A creative brief (9 elements) |
| One-shot, hope for the best | A revision loop (2–3 rounds; specify change AND keep) |
| Generic reader assumed | Audience + Constraints make it specific |
| No standard | Quality Criteria the output is judged against |
| Start from scratch each time | A saved template + personal archive |

---

## In scope / out of scope

**In scope.** Writing the brief: filling the 9 elements, choosing the minimum viable subset, running the revision loop, avoiding the 10 common mistakes, building the template library and archive.

**Out of scope.** The *facts* the prompt cites (verified upstream), the *fear* it opens with (mapped upstream), the *page structure* it fills (defined upstream), and final editorial judgement on the draft (a separate quality-control discipline). This skill produces the brief that turns those inputs into a usable draft.

---

## What "good" looks like

- The prompt contains all 9 elements (or a deliberate minimum-viable subset), each filled with specifics — no placeholders.
- Inputs carry real facts (cited, e.g. by Source Bank C-ID) and a real style example.
- Quality Criteria are stated, so the draft can be judged, not just accepted.
- The output is **70%+ usable on the first pass**; the revision loop closes the rest in 2–3 rounds.
- The prompt is saved to the library/archive for reuse.

This skill is complete when the 9-element system, the template library, and the personal archive exist for the proof niche, the system is shown working on real pages, and the audit passes.
